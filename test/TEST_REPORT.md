## 二、发现的问题与说明

### 1. 媒体键被系统全局劫持（已确认非 bug）
- 现象：映射 keyevent 88（KEYCODE_MEDIA_PREVIOUS）后按 88 不执行 NUI 映射。
- 原因：`MediaSessionService` 将媒体键全局路由给当前音乐 App（logcat 证据），NUI 的 `dispatchKeyEvent` 收不到。
- 处理：验证按键执行需用非媒体键（66 验证通过）；**车机若方向盘发媒体键需另议**（已在 TEST_SPEC T35 记录）。

### 2. 240dpi 下桌面设置入口点击失效（模拟器，待真车确认）
- 现象：`wm density 240` 后 page1 布局正常重算（4 图标/行），但点击"桌面设置"图标无反应（320dpi 正常）。
- 可能：BlueStacks input 坐标映射问题，或 240dpi 下点击热区异常。
- 建议：真车（dpi 240）复测；若复现需查 ViewPager 点击命中逻辑。

### 3. 高德/酷我等 App 抢前台（测试环境问题）
- 高德按 T02 逻辑每 5s 自动拉起，验证中需 `force-stop` 后再操作 NUI；**巡航卡验证例外**（force-stop 会断广播源，见 TEST_SPEC T40）。

### 4. 无系统 TTS 时语音置灰（预期）
- 模拟器无 TTS 引擎：声音面板红字提示"系统语音不可用"，男声置灰不可点——可用性检查逻辑符合预期，非 bug。
